## Relevant guidance

- Build landing page, onboarding, then fast delivery of the useful result. Add communication features after these work.
- Start with one specific user and job. Build one user story at a time rather than designing a general platform first.
- Onboarding should resolve the customer's largest points of friction or fear. Keep it small, explain unfamiliar steps in the flow, and use a tiny practice experience where appropriate.
- Interface need not be a conventional app. The handbook recommends Convex for business logic and database, but this is guidance, not a selected project stack.
- Reuse an existing AI agent system rather than building one. Hermes is linked as an example; no agent platform has been selected for this project.
- Define milestones and check that each actually works. Keep project context, plans and progress in Markdown; the handbook recommends GitHub. No repository was created or published in this step.
- The page lists 3–9 October for building and 10–17 October for shipping. Its weekend completion target is course guidance, not a claim about project readiness.
